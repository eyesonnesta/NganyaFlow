# Contributing to NganyaFlow

Read the [documentation index](docs/README.md) before changing a flow or data contract. Use a focused branch and pull request. Describe the problem, final behavior, relevant validation and known limits. Keep implementation status honest.

For UI changes, include screenshots for light/dark mode and describe accessibility checks. For data/ML changes, include schema versions, provenance, reproducible splits and baseline comparisons; never claim unmeasured accuracy. For offline changes, test duplicate retry and process recreation.

Never commit credentials, assigned access codes, raw field observations, precise user locations or personal identifiers. Use synthetic fixtures labelled as such. External datasets retain their own licences. Prefer repository documentation over a duplicate Wiki so changes are reviewed together.
